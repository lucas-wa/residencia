# Dependencias para rodar o benchmark no cluster UFG (H100) dentro do container

# Serve para QUALQUER base que ja tenha torch + CUDA instalados: tanto o container do
# cluster (slurm_run.sh) quanto a imagem "Deep Learning VM" da GCP numa VM unica com L4
# (run_gcp.sh, onde o venv e criado com --system-site-packages para herdar esse torch).
#
# NAO inclui torch: a imagem vLLM ja traz torch + CUDA casados com o driver do no.
#   Reinstalar torch por pip quebraria a instalacao de CUDA do container. Isso NAO e so
#   uma preferencia: quando o `uv pip install --system` falha (site-packages read-only) e
#   os runners caem no `pip install --user`, o pip resolve a arvore inteira e QUALQUER dep
#   que declare torch (colpali-engine, peft, bitsandbytes) arrasta um torch proprio para
#   $HOME/.local. Esse torch vem sem as libs CUDA do no (`ImportError:
#   libnvJitLink.so.12`), e como o --user vem ANTES no sys.path ele sombra o torch bom da
#   imagem. Por isso os runners tem o guard `prefer_host_torch` (slurm_run.sh,
#   run_gcp.sh, finetune/slurm_finetune.sh, finetune/run_gcp_finetune.sh), que limpa o
#   torch do --user/venv depois de instalar as deps. Mantenha torch FORA deste arquivo.
# NAO inclui bitsandbytes: ele so e usado no QLoRA (`finetune/train_lora.py` com
#   METHOD=qlora) e e um dos que arrastam torch pela resolucao acima. Quem precisa dele e
#   so `finetune/run_gcp_finetune.sh`, que o instala sob demanda com `--no-deps` quando
#   METHOD=qlora. O benchmark e o LoRA bf16 da H100 nao o tocam.
# NAO inclui faiss: benchmark/common/index.py cai para busca por produto interno em
#   numpy quando faiss nao existe, e os corpora aqui sao pequenos (mesmo top-k).
# NAO inclui flash-attn: os wrappers de modelo caem para attn_implementation="eager".
#
# TODO confirmar em runtime: o container ja traz um `transformers` proprio (exigido pelo
# vLLM) e o pin abaixo pode conflitar com ele. Nao e preciso adivinhar: o estagio
# `preflight` (`python3 -m benchmark.check_env`) le as versoes instaladas e diz qual
# caminho de carregamento do ColQwen2 sobrou.
#
# FAIXA DO TRANSFORMERS -- os dois tetos ja tentados aqui e por que a faixa e esta:
#
# 1) O teto `<4.51` FOI REMOVIDO: em imagens recentes (ex.: Deep Learning VM da GCP com
#    torch 2.9/cu129) ele conflitava com as outras deps -- `mteb`/`sentence-transformers`
#    pedem um transformers mais novo e o pip terminava em ResolutionImpossible.
#
# 2) Sem teto NENHUM, porem, o pip sobe para transformers 5.x (hoje 5.21) e o
#    `v3_jinav4` MORRE no from_pretrained. O jina-embeddings-v4 e custom code e
#    VENDORIZA uma copia de `qwen2_5_vl.py` no proprio repo do Hub; essa copia faz
#        self.rope_init_fn = ROPE_INIT_FUNCTIONS[self.rope_type]   # rope_type="default"
#    e o transformers 5.0.0 REMOVEU a chave "default" de
#    `transformers.modeling_rope_utils.ROPE_INIT_FUNCTIONS` (restaram linear/dynamic/
#    yarn/longrope/llama3/...). Resultado no cluster: `KeyError: 'default'` ao carregar
#    `jinaai/jina-embeddings-v4`. O codigo e do repo do checkpoint, nao nosso -- nao da
#    para corrigir do nosso lado; o que resta e nao deixar o transformers passar de 5.
#    Dai o teto `<5`. Quando o jina republicar o modeling contra a API do 5.x, este teto
#    pode cair.
#
# O piso `>=4.57` vem dos outros dois do trio: Qwen3-VL-Embedding (card:
# `transformers>=4.57.0`; o `Qwen3VLForConditionalGeneration` NATIVO so existe a partir
# do 4.57.0 -- nao ha custom code aqui) e Nemotron ColEmbed V2 (card:
# `transformers>=4.57.2`; o custom code importa de
# `transformers.models.qwen3_vl.modeling_qwen3_vl`). O jina pede `>=4.52.0`, ja coberto.
#
# A faixa `>=4.57,<5` e viavel com TODO o resto -- quem a aperta de verdade e o
# `colpali-engine`, que pina transformers por release dentro da propria serie 0.3.x:
# 0.3.10 pede <4.52, 0.3.11/0.3.12 pedem <4.54, 0.3.13 pede `>=4.53.1,<4.58` e de 0.3.14
# em diante ja exige `>=5.0`. Com o teto `<5` o pip retrocede sozinho ate o 0.3.13 e
# fecha em transformers 4.57.x -- verificado com `uv pip compile` (py3.11/3.12/3.13):
# transformers==4.57.6, colpali-engine==0.3.13, peft==0.17.1, sentence-transformers==5.7.0,
# mteb==2.26.28. Sem ResolutionImpossible. `mteb` (>=4.40,<6) e `sentence-transformers`
# (o 6.x pede >=5.0, mas a serie 5.x pede `>=4.41,<5`) acomodam os dois lados.
# NAO se adivinha o que sobrou na imagem: o estagio `preflight`
# (`python3 -m benchmark.check_env`) le as versoes instaladas e diz qual caminho de
# carregamento do ColQwen2 vale -- colpali-engine quando a faixa bate (ele exige
# transformers >4.46.1), senao o caminho NATIVO do transformers: >=4.49 ja traz ColQwen2

#
# O cap de `colpali-engine` (<0.4) fica como esta -- a API usada pelos wrappers e a da
